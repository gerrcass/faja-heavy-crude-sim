# Retro — 2026-10-23

## What worked

- The spec → tickets → implementation chain kept the scope concrete. The spec's six stations survived into the figure, the simulator and the prose.
- The Anatomy cutaway is the right centerpiece. The quarry-bench reservoir reads as geology, and the line-end check plus the 31-check browser QA caught real geometry and layout faults.
- The static Vite + GitHub Pages path is simple and durable: no backend, no secrets, no runtime dependency.
- The README screenshot and the OG/favicon set make the project feel finished rather than like a branch demo.

## What to change next time

1. **Commit early, commit often.** The delegated session worked for a long time before its first commit. A commit after the shell, after the figure, and after the control desk would have made hand-off and review much safer.
2. **Keep one writer for shared surfaces.** Parallel work on `index.html` produced duplicate meta tags and two `<noscript>` blocks. Assign `index.html`, `package.json` and the global styles to one implementer, or serialize edits through the integration branch.
3. **Timebox the polish loop.** The line-end and visual iterations were productive but open-ended. Set a hard "ship the current quality" checkpoint after the first green QA, then spend a fixed extra pass on the figure.
4. **Put the checks in CI.** `npm run check` and `npm run qa` are strong; add them to a pull-request workflow so the gate is visible on the PR, not only on a local terminal.
5. **QA the agent-facing contract too.** The first delegated QA script used `require` in an ESM file and failed only when run. Add a tiny `node --check`/smoke test for every tool script, or keep the QA in the same `.mjs` style as the app.
6. **Use the reduced-motion and reveal checks.** The final QA covers the interaction, but a dedicated reduced-motion assertion and a reveal-visibility assertion are cheap and catch accessibility regressions.
